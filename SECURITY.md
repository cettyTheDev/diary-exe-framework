# Security policy

## Supported version

Security fixes target the current `main` branch.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting. Do not place credentials,
private source material, personal data, private API locations, or exploit
details in a public issue.

For non-sensitive bugs, open a regular issue with reproduction steps, the
affected route, and the browser or runtime version.

## Data boundary

The public repository contains synthetic fixtures only. A report that requires
real source material should describe the behavior without attaching that
material.
